## 结论

真实执行了 GPU 训练、生成和评估，但当前恢复器没有取得几何与动力学的共同改善，不合入默认模型。
生成 Cα 加小型恢复网络降低总体键长误差和碰撞，却进一步压低运动幅度、增大跨残基键误差。
真实 Cα oracle 明显改善结果；额外的局部坐标系对照说明，残基方向建模也是当前设计的缺项。
这不是“分层模型已经有效”，也不足以否定更完整的分层生成方案。

## 实际实现与实验边界

- 冻结现有 A1，真实采样全原子轨迹后只取 Cα；恢复器不能读取生成的非 Cα 原子，更不能读取真实未来非 Cα 原子。原始全原子输出仅用于 A1 对照评分。
- 恢复器为 92,032 参数、三层等变图网络：观察到的四帧、化学拓扑、物理查询时间和明确的 Cα 条件进入模型；逐层硬固定 Cα。它不是新训的 Cα 生成器或完整分层预训练模型。
- clean 臂只用真实 Cα 训练；mixed 臂交替使用真实/生成 Cα。各两训练种子（71/72）、512 次更新，初始化/样本顺序/优化器匹配；四个最终 checkpoint 全部评分，无验证集选点。
- 32 个 train 体系、每体系两个窗口，共64训练片段；8 个既有 valid 体系、每体系两个不重叠窗口，共16验证片段。历史4帧、未来12帧，均100ps间隔。训练生成种子11，验证生成种子17/29。
- 损失预先固定为残基内相对坐标 MSE + 实际共价键长 MSE，权重1:1。生成 Cα 条件下，真实残基内偏移仅作损失目标。
- 目前仅蛋白质；不支持的小分子输入显式拒绝。没有打开 sealed test，没有改 PVB/BioKinema，没有更新 A1，也没有合入 Mamba。

完整协议：[PLAN.md](PLAN.md)。实现入口为 `molvid/geometry/ca_detail.py`、`molvid/codec/ca_detail.py`、`molvid/training/ca_detail.py` 和 `molvid/evaluation/ca_detail.py`。

## 配对验证结果

下表先在体系内平均窗口/生成种子，再对8体系等权平均。学习模型行额外平均两个训练种子；不是把随机种子当独立体系扩大样本量。
总体/跨残基键误差为 Å；碰撞为每千原子；MSD MAE 为 Å²；RMSF 幅度比的理想值为1。
oracle 使用真实未来 Cα，是辅助诊断，不是可部署预测。

| 条件与恢复方式 | 总体键误差↓ | 跨残基键误差↓ | 碰撞↓ | MSD MAE↓ | RMSF 幅度比 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原始 A1 全原子生成 | 0.270 | 0.368 | 109.90 | 3.045 | 0.823 |
| 生成 Cα + 刚性平移 | 0.213 | 0.600 | 83.83 | 3.669 | 0.679 |
| 生成 Cα + clean 恢复器 | 0.198 | 0.514 | 71.21 | 3.660 | 0.671 |
| 真实 Cα + clean 恢复器（oracle） | 0.146 | 0.333 | 20.48 | 1.231 | 0.828 |
| 生成 Cα + 局部坐标系旋转* | 0.168 | 0.467 | 119.48 | 2.854 | 0.920 |
| 真实 Cα + 局部坐标系旋转*（oracle） | 0.054 | 0.104 | 16.74 | 0.527 | 0.935 |

星号为初步结果出现后、执行前补充登记的探索性几何对照：用共价相邻残基的 Cα 构造局部坐标系，旋转并平移最后观察帧的残基偏移；不训练、不增加 A1 采样。退化坐标系显式回退平移，本次窗口中回退比例为0。不能把这个事后对照说成独立预注册验证。

关键解读：

1. **平均几何改善掩盖链连接退化。** clean/seed71 相对 A1 的总体键误差变化为 −0.0726 Å，体系配对 bootstrap 95%区间 [−0.0788, −0.0673]；但跨残基键误差增加0.1476 Å，区间 [0.1330, 0.1646]。
2. **运动退化不是 Cα 被网络改坏。** Cα 全程固定，生成条件的 Cα RMSE 始终1.904 Å；原子 RMSF 却从0.823降至约0.671。当前确定性恢复器继承、甚至加重刚性搬运的细节运动不足。不能靠降低运动换几何分数。
3. **小网络的增益有限。** 相对不训练的平移基线，clean 恢复器把碰撞83.83降到71.21，但细节 RMSE 仅从1.051降到1.029 Å。这里细节误差以各原子相对其所属 Cα 的偏移计算，包含零误差的 Cα。mixed 两种子没有相对 clean 的一致综合优势。
4. **oracle 揭示了两个瓶颈。** 真实 Cα 给 clean 恢复器仍只有1.022 Å细节 RMSE；加入无参数方向搬运后降为0.910 Å。这提示方向表示不足，不能把所有问题都归于骨架。但在生成 Cα 上，同一方向搬运将细节误差升至1.234 Å、碰撞升至119.48；较好的运动幅度并不代表运动模式正确。
5. **不能当作热力学或分布验收。** 随机生成和单条真实轨迹的逐点误差只是描述量；短片段 MSD/RMSF 也不是平衡分布、转移速率、跨时间间隔一致性或泛化能力的证明。只有既有8个开发体系、固定100ps，尚非独立测试。

原始结果：[主评估](../../runs/ca_detail_20261005/evaluation/summary.json)，[方向对照](../../runs/ca_detail_20261005/frame_control/summary.json)。包含全部训练种子、逐体系指标、角度/扭转等指标和主实验配对区间；坐标产物也保留在对应运行目录。

## 真的执行了什么，为什么快

环境为 `enter-container` → `torch-ito`，PyTorch 2.5.1+cu121，A100-SXM4-80GB。
不是仅生成脚本/伪造完成状态；保存了实际 GPU 身份、每2秒 nvidia-smi 监控、逐步训练记录、初始/最终参数、优化器状态、SHA 和重载验证。

| 阶段 | 实际工作量 | 记录耗时 |
| --- | --- | --- |
| 冻结 A1 生成 | 96次真实采样，80个缓存记录 | 282.03秒 |
| clean 训练 | 两模型各512次更新 | 15.28 / 14.09秒 |
| mixed 训练 | 两模型各512次更新 | 13.06 / 13.98秒 |
| 主评估 | 288条配对评分 | 122.11秒 |
| 补充方向对照 | 48条评分，0次训练更新 | 22.07秒 |
| CUDA 定向测试 | 3个测试通过 | 4.38秒 |

耗时是各 runner 记录的阶段 wall time，不等于从任务开始到结束的全部耗时；两训练臂并行，不能简单相加当总 wall time。CUDA event 为流上经过时间，也不冒充纯计算利用时间。

快的直接原因：A1 冻结并缓存，新训的是9.2万参数的局部恢复器，不是完整 DiT。这个规模的512步仅是机制验证，不能声称充分训练。
四个 checkpoint 的全部 AdamW step 都是512，初末参数差 L2 为6.86–7.11；重载输出一致。随后另起过程在 GPU 上重新加载所有初始/最终 checkpoint，固定64训练片段重算，损失及输出确实改变。这验证训练发生，不替代独立泛化验证。

代码身份：缓存 `5ea5f2a`；训练 `3f0f426`；主评估 `a2bf0ac`；checkpoint 复算 `657217d`；方向对照和最终3项测试 `a6ca1cb`。每阶段记录自己的源身份，不把最终文档提交冒充运行源码。

此前快速实验也不能笼统说成全部重训：U/K 是冻结特征小 head，N1 是推理，N2 是旧结果聚合，N4 是 CPU 统计。本次检查27个历史 U/K checkpoint，均记录2000次优化更新；选一个旧 U 模型在 GPU 上完整复算原验证指标，最大绝对差为0。无法补证过去没有保存的 GPU 利用率曲线，也没有逐步重放所有历史训练。
