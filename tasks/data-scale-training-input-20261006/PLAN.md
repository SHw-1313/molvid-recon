# TRAIN512 input-only controlled experiment

Independent source branch from967114b. Preserve current GPU campaigns. Only
optional data expansion is wired into the existing trainer; no architecture,
precision, loss, static mixture, history/time backend, optimizer or parent changes.
Default recipes retain their original schedule/contract except runtime hashes.

The candidate recipe must be byte-SHA bound to a registered query-depth control
and identical after removing coordinate_data_scale. The new field binds full512
concat qualification, closed immutable shard inventory and matched calendar.
Load that frozen8192-entry manifest, not a newly randomized approximation. Verify
every update's physical lag, view, H, clip count, auxiliary flag against original;
preserve original normalization, base192 dataset indices and shard-local pointers.
Log both candidate batch identity and original reference schedule index.

CPU loader qualification is not training. The actual trainer first requires
completed uncropped maximum H4/H8 CUDA updates plus exact cold resume at both
depths, before constructing any model. Failure stops rather than excluding large
systems, shortening clips or changing precision. A single maximum probe does not
bound all topology-dependent memory; selected-largest and both-seed exact-resume
qualification through the actual data loader remain required before formal runs.

At implementation time: no full512 formal training submitted; full corpus
materialization/calendar audits and CUDA gate are still live prerequisites.
Real-data loader audit, default control update parity, new-prefix/cold-resume and
eventual fixed-final paired48 evaluation are separate evidence stages. A reused
development panel is not an independent test, and equal updates/calendar do not
mean equal atom exposure, coordinate noise arrays, compute or system visitation.
